# AI Agent Skills 配置戦略

## 目的

Firebase の設計・実装・レビューに関する知見を、Codex / Claude の双方が同等に参照できる状態をプロジェクト内で維持する。

## 背景

`docs/strategy-modularization.md` では、次の優先順位が明示されている。

1. 再利用性
2. シンプルさ
3. その他マルチモジュールの利点（拡張性、テスト容易性、ビルド速度）

本方針に従い、AI 向けナレッジでも「重複を許容して再利用性を優先」する。

## 採用方針

Firebase Agent Skills（`firebase/agent-skills`）を、次の 2 つの配置先に同一内容で配置する。

- `.codex/skills/`
- `.claude/skills/`

### なぜこの設計か

- Codex と Claude は、スキル探索パスが異なる。
- そのため単一ディレクトリへの配置よりも、各エージェントの標準探索パスに合わせて明示配置した方が、初期セットアップと運用の失敗率を下げられる。
- これは `docs/strategy-modularization.md` の「再利用性を最優先し、シンプルさの低下を許容する」方針に整合する。

## 運用ルール

- Skills 更新時は `.codex/skills` と `.claude/skills` の両方を同時更新する。
- 片方のみの更新は禁止する（エージェント間の回答差分を防止するため）。
- 新規 Skills 追加時も同様に 2 箇所へ追加する。

## 採用しなかった代替案

### 代替案 1: 共有ディレクトリ 1 箇所のみに配置

- 概要: 例として `.skills/` だけに配置し、各エージェント側設定で参照させる。
- 不採用理由:
  - エージェントごとに追加設定が必要となり、環境差異・オンボーディング失敗の原因になる。
  - issue の完了条件である「Codex, Claude が使用できる箇所に配置」を満たしにくい。
- 有効になり得る条件:
  - 開発メンバーが少なく、全員が同一のエージェント設定を厳密管理できる短期検証。

### 代替案 2: 各開発者のホームディレクトリ（`~/.codex/skills` など）のみで管理

- 概要: リポジトリに含めず、個人環境へ都度インストールする。
- 不採用理由:
  - リポジトリ外のため再現性が低い。
  - レビュー時に「どの Skills を前提にした提案か」が共有されず、設計判断の一貫性が下がる。
- 有効になり得る条件:
  - POC や個人開発など、再現性より素早い試行を重視する場合。
