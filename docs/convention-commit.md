# コミット規約

## 目的

本ドキュメントは、コミットを差分の履歴ではなく、変更意図の証跡として残すことを目的とする。

## 基本方針

本プロジェクトのコミット規約は Conventional Commits をベースとする。

参考：[Conventional Commits 1.0.0](https://www.conventionalcommits.org/ja/v1.0.0/)

- `type` は Conventional Commits に従う
- `summary` と `body` は日本語で書く

## 形式

```text
<type>: <summary>

<body>
```

- `summary` に差分の概要を端的に書く
- `body` に変更意図を書く。変更した理由や採用した設計、採用しなかった代替案やその理由など
- レビュワーの視点に立ち、`summary` だけ意図が伝わらないと判断した場合は、必ず `body` を書く

### `body` を記述する理由

- AI エージェントによる膨大な量の差分と、その変更意図を人間が追えるようにするため
- AI エージェントがプルリクエストを作成するとき、プルリクエスト本文に変更意図を反映するため

## 型

| 型          | 用途                               |
|:-----------|:---------------------------------|
| `build`    | ビルドシステム、Gradle、依存関係、CI などの変更     |
| `ci`       | CI 設定やスクリプトの変更                   |
| `docs`     | ドキュメントのみの変更                      |
| `feat`     | ユーザー向け機能の追加                      |
| `fix`      | ユーザー向け不具合の修正                     |
| `perf`     | パフォーマンス改善                        |
| `refactor` | 振る舞いを変えないコード構造の改善                |
| `test`     | テストの追加または修正                      |
| `chore`    | 上記に当てはまらない保守作業                   |
| `style`    | フォーマットなど、意味に影響しない変更（UI の変更は含まない） |
| `revert`   | 既存コミットの取り消し                      |

## コミット粒度

コミットは、取り消してもビルドが通る最小単位の意味のまとまりとする。

無理に細かく分割しないが、人間が後から読み返したときに「何を、なぜ変更したか」を理解できる粒度にする。

### コミット例

1. ドメインモデルと Repository インターフェースの追加
2. データモデルと Repository 実装クラスの追加
3. データレイヤの具体実装モジュールの実装
4. 機能モジュールの ViewModel の実装
5. 機能モジュールの UI 実装

## 禁止事項

- 絵文字プレフィックス（例：`:sparkles:` や `✨`）を使用してはならない
